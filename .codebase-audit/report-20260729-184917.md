# Codebase Audit Report — arbgrid (polymarket-arb-scanner)

Generated: 2026-07-29
Scope: Full Python codebase (~280 files)
Method: 3-lens adversarial verification; all 138 findings below survived all three lenses.

## Executive Summary

Verdict: The codebase has systemic correctness and security gaps across execution, metrics, testing, and API integration layers. Several findings are financially material and block live-trading activation.

| Severity | Count |
|----------|-------|
| High     | 15    |
| Medium   | 67    |
| Low      | 56    |
| Total confirmed | 138 |
| Unverified | 0 |

Note: Two pairs of findings describe the same underlying defect (metrics.py histogram double-counting appears twice; finnhub_api.py resp.json() appears twice). They are retained as listed by the verification pipeline.

Critical concerns for live-trading readiness:
1. WS-triggered arbs are silently dropped (wrong asyncio loop) -- no WS-driven cross-platform arb executes.
2. Smarkets and SX Bet hedge legs are 2x oversized due to unit mismatch.
3. Treasury daily transfer limit has a TOCTOU race that allows the cap to be breached.
4. LogicalArb opportunities carry zero profit metadata -- every executed trade is logged as $0.
5. Prometheus metrics emit wildly incorrect histogram values.

## HIGH Findings (15)

H-01 continuous.py:1277 -- WS callback thread uses wrong asyncio event loop, silently dropping all priority-queue items
In Python 3.10+ asyncio.get_event_loop() from a non-asyncio thread returns a new idle loop. run_coroutine_threadsafe schedules on the idle loop; the future is created but never consumed. Every WS-triggered cross-platform arb is permanently lost. Same bug at line 1312.
Fix: Capture asyncio.get_running_loop() inside _continuous_loop into a nonlocal _main_loop; use it in on_price_update.

H-02 hedger.py:260 -- _hedge_smarkets passes contracts count instead of dollar amount
size/fill_price gives a contract count; SmarketsClient.place_order() expects dollars and multiplies by 100 internally. A $50 hedge at probability 0.5 produces quantity=100, interpreted as $100 -- 2x oversized.
Fix: Pass size directly as the dollar amount.

H-03 hedger.py:277 -- _hedge_sxbet same unit mismatch as H-02
Identical root cause. SXBetClient.place_order() expects dollars; the calculation passes a contract count. Every SX Bet hedge leg is doubly oversized.
Fix: Pass size directly.

H-04 metrics.py:286 -- Prometheus histogram emits cumulative sums of already-cumulative values
observe() already stores cumulative counts. get_prometheus_text() re-accumulates them with cumulative +=, producing sums of cumulative sums. For observations {0.5, 2.0, 10.0} the output reads 1, 3, 6 instead of 1, 2, 3. All Grafana histograms and quantile estimates are wrong. (Also appears as a duplicate finding in the input list.)
Fix: Emit entry["buckets"][bucket_bound] directly; remove the cumulative accumulator.

H-05 credential_health.py:108 -- CRITICAL alert never fires on exception-path failures
Real platform outages raise exceptions; the if fail_count==3: _fire_credential_alert(CRITICAL) check lives only in the else branch (returned-False path). Three consecutive platform-down failures never trigger the CRITICAL alert.
Fix: Duplicate or move the fail_count check and alert call into the except block.

H-06 scans/rewards.py:231 -- outcomePrices string not converted to float; crashes on arithmetic
Polymarket's outcomePrices returns stringified floats. prices[0] is a string; every arithmetic operation in _calculate_optimal_quotes raises TypeError.
Fix: yes_price = float(prices[0])

H-07 scans/logical_arb.py:86 -- LogicalArb dict missing net_profit, net_roi, total_cost, prices, confidence
executor.py reads net_profit as 0 for every LogicalArb trade. scan_roi=0 causes API-error paths to reject. capital_efficiency_score returns 0, ranking all LogicalArb last. The imported POLYMARKET_DEFAULT_TAKER_RATE is never used, confirming fee calculation is absent.
Fix: Compute net profit with the fee rate and populate all required fields.

H-08 broker/validator.py:245 -- move_capital caps check double-counts intra-portfolio capital
portfolio + amount inflates the total as if new external capital arrived. With portfolio=$500, ceiling=$600, amount=$150: the check fires ($650>$600) blocking the rebalance even though the actual portfolio remains $500.
Fix: Remove the if portfolio + amount > ceiling check.

H-09 scripts/analytics.py:106 -- Sharpe ratio formula computes annualized volatility, not Sharpe ratio
THEN stddev * SQRT(252) is annualized standard deviation. The Sharpe ratio is (avg_pnl / stddev) * SQRT(252). High mean / low variance strategies report lower "Sharpe" than high-variance strategies, inverting risk-adjusted ranking.
Fix: CASE WHEN stddev > 0 THEN (avg_pnl / stddev) * SQRT(252) ELSE NULL END

H-10 tests/integration/verify_fees.py:244 -- Gemini fee verification uses superseded formula
Uses min(P, 1-P) * GEMINI_FEE_RATE; correct formula per CFTC 40.6 filing (2026-03-09) is roundup(rate * C * P * (1-P)). Also imports deprecated GEMINI_FEE_RATE=0.05 instead of GEMINI_MAKER_RATE/TAKER_RATE.
Fix: Update to new formula and correct rate constants.

H-11 tests/test_treasury.py:185 -- Idempotency test allows double-withdrawal to pass silently
Test comment explicitly states "the live withdraw is called twice". No assertion on gemini.withdraw_usdc.call_count. Two real USDC withdrawals can be submitted while the test remains green.
Fix: Assert gemini.withdraw_usdc.call_count == 1; fix production to query DB before calling withdraw_usdc.

H-12 mm_pilot.py:242 -- SSRF via unvalidated SUPABASE_URL exfiltrates Supabase service key
SUPABASE_URL has only a non-empty check. If set to an attacker-controlled host, every fetch_control() call sends the Supabase service key in apikey and Authorization headers. assert_public_url() exists and is used elsewhere but not here.
Fix: self._url = assert_public_url(url, env_name="SUPABASE_URL", allow_http=False)

H-13 treasury.py:142 -- TOCTOU race allows daily transfer limit bypass under concurrent calls
Two concurrent execute_transfer calls can both read the same used_today, both pass the limit check, and both proceed to real fund movements. The idempotency key only deduplicates identical-parameter calls.
Fix: Acquire self.db._lock for the entire span from limit check through log_transfer.

H-14 reddit_api.py:111 -- _authenticate sets authenticated=True when access_token is None
data.get("access_token") returns None on malformed response. Code writes "Authorization: Bearer None", sets authenticated=True, returns True. All subsequent calls fail with 401 but is_authenticated() keeps returning True.
Fix: if not self._access_token: return False before updating the session header.

H-15 (same as H-04 duplicate) -- get_prometheus_text() double-counts already-cumulative values
See H-04.

## MEDIUM Findings (67)

### Execution and Logic Bugs

M-01 fees.py:34 -- EV fee formula reverses probability weights
return prob_a * case_b_fees + (1.0 - prob_a) * case_a_fees should be prob_a * case_a_fees + (1.0 - prob_a) * case_b_fees. Produces incorrect expected fees for every cross-platform arb using FEE_MODEL='expected_value'.

M-02 executor.py:238 -- Balance cache race condition in concurrent WS-triggered execute() calls
_balance_cache, _balance_cache_ts, _balance_cache_type read/written without lock from concurrent threads. Risk gate decisions made on partially-updated cache state.

M-03 executor.py:2705 -- _whale_copy_position_count never decremented on settlement
After WHALE_COPY_MAX_POSITIONS (default 5) trades, WhaleCopy is permanently blocked for the process lifetime. check_settlements() does not touch the counter.

M-04 betfair_api.py:204 -- list_markets/list_runners bypass circuit breaker
Direct self.session.post() calls skip @retry and _circuit.is_open() checks. Failures in these methods are not recorded as circuit breaker events.

M-05 risk_manager.py:94 -- Cross-platform balance check assumes equal leg cost
half_cost = trade_cost / 2 used for both platforms. A trade at prices 0.30/0.65 has legs costing $0.30 and $0.65, not $0.475 each. A platform with $0.50 passes the check but cannot fund its $0.65 leg.

M-06 ws_feeds.py:271 -- Never-connected platforms appear healthy
_last_message_time defaults to now for unseen platforms, so (now - now) = 0, never stale. A feed that failed to connect reports as healthy.
Fix: Default to 0 (epoch) instead of now.

M-07 sxbet_api.py:121 -- _RateLimitError from open circuit propagates unhandled
_request raises _RateLimitError with no @retry decorator; callers like fetch_all_markets have no catch. The exception crashes the scan thread rather than returning None gracefully.

M-08 gemini_api.py:314 -- 2-outcome categorical events misclassified as binary
event_type = event.get("type") or ("binary" if len(contracts) == 2 else "categorical"). A 2-outcome categorical market (A vs B) is misclassified as binary.
Fix: event_type = event.get("type") or "categorical"

M-09 event_monitor.py:271 -- Platform price pollutes consensus used to measure divergence against itself
Platform price added to signal_aggregator before computing consensus, then divergence computed as |platform_price - consensus|. The platform's own price pulls consensus toward itself, systematically understating divergence.

M-10 recovery.py:262 -- Non-atomic log_partial_fill + update_trade_status creates duplicate hedges on recovery
Crash between the two DB operations leaves trade as orphaned. Next startup re-runs both steps, creating duplicate partial_fill records and potential duplicate hedges.

M-11 correlation_tracker.py:108 -- Price out-of-range filter only drops exactly 0 and 1
Outer: if price <= 0 or price >= 1. Inner: if price == 0 or price == 1: continue. Prices like -0.5 or 1.01 fall through and contaminate Pearson calculations.
Fix: if price <= 0 or price >= 1: continue (remove inner guard)

M-12 calibration_tracker.py:104 -- Cache invalidation runs outside the lock
dict iteration and deletion occur after _lock is released. Concurrent threads produce KeyError; fresh entries written between threads' deletions are silently lost.

M-13 credential_health.py:78 -- check_all_platforms awaits coroutines sequentially
Calling async def returns a coroutine object; storing in a list then awaiting serially achieves no concurrency. Worst case: 8 platforms x 30s = 240s.
Fix: Use asyncio.gather(*coros, return_exceptions=True).

M-14 supabase_sync.py:342 -- DB access without lock in get_remote_high_water_mark else-branch
with self._db._lock: block ends at line 335; else branch at line 342 calls self._db.conn.execute() without the lock.

M-15 finnhub_api.py:106 -- resp.json() called 2-3 times; AttributeError on JSON null
isinstance(resp.json(), list) calls json twice; if response is JSON null, resp.json() returns None; None.get("data", []) raises AttributeError. (Also appears as a duplicate entry in the input list.)
