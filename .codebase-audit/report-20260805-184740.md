## Executive Summary

**Verdict:** The codebase has systemic correctness and security defects that go beyond isolated edge cases. Seven findings directly corrupt financial calculations that drive every trade decision (inverted fee weights, wrong Sharpe, wrong max drawdown, broken reward estimator, wrong guaranteed-gain formula, dead Layer-4 gate, convergence fee miscalculation). Two findings create SSRF/credential-exfiltration paths that can redirect authenticated requests carrying admin-level Supabase service keys to attacker-controlled hosts. Several tests are vacuous — they pass regardless of whether the code under test works — providing false confidence on critical paths including double-withdrawal idempotency and exchange circuit breakers.

**Finding counts:** 125 confirmed, 0 unverified
**By severity:** 13 high — 52 medium — 60 low

Note: two pairs of findings are near-identical duplicates surfaced by separate audit lenses (the Sharpe-ratio bug appears twice at scripts/analytics.py:106; max drawdown appears at both high and medium; credential_health.py sequential-execution appears at lines 74 and 75). All 125 are listed; duplicates are flagged inline.

### H-01 Inverted fee-weight formula corrupts net profit for all cross-platform scans
**File:** fees.py:34
**Evidence:** `return prob_a * case_b_fees + (1.0 - prob_a) * case_a_fees`
**Why it matters:** Weights are exactly reversed. FEE_MODEL defaults to 'expected_value', so net_profit_cross_betfair, net_profit_cross_smarkets, net_profit_triangular, and net_profit_cross_generic all report wrong net profit. Trades that appear profitable at scan time may be unprofitable at execution.
**Fix:** `return prob_a * case_a_fees + (1.0 - prob_a) * case_b_fees`

### H-02 Fail-open: PM triangular opportunities pass through when token IDs or CLOB data are missing
**File:** scans/triangular.py:407
**Evidence:** Both failure paths (missing token IDs, missing CLOB data) call `refined.append(o); continue` — propagating instead of dropping.
**Why it matters:** Opposite of the fail-closed policy in _refine_cross_with_clob. PM-involved triangular opportunities carrying only stale mid-prices reach the executor and can generate real losing orders.
**Fix:** Replace both `refined.append(o); continue` stubs with `continue` only.

### H-03 `guaranteed_gain` formula ignores current market price
**File:** scans/time_decay.py:81
**Evidence:** `guaranteed_gain = buy_below_price - target_price`
**Why it matters:** The actual gain is `target_price - current_price`. When consensus_prob == buy_below_price (both default 0.95), guaranteed_gain is 0 for the strongest possible signal. When consensus_prob > buy_below_price (e.g. 0.97 vs 0.95), result is -0.02 — negative for a profitable trade. All downstream sorting on _guaranteed_gain is corrupted.
**Fix:** `guaranteed_gain = target_price - current_price`

### H-04 `LogicalArb` opportunity missing `if_market` token IDs, making arb unexecutable
**File:** scans/logical_arb.py:84
**Evidence:** `"_token_ids": token_ids` stores only then_market tokens; no field for if_market token IDs.
**Why it matters:** Executor can only execute one leg, turning the "arbitrage" into an unhedged directional bet retaining full event risk.
**Fix:** Add `"_if_token_ids": _extract_token_ids(if_market)` to the dict; update `_build_legs` in executor.py for the second leg.

### H-05 `reward_metric_to_event` crashes with TypeError when timestamp column is NULL
**File:** supabase_sync.py:50

**Why it matters:** Crashes upsert_events for any reward row with a NULL timestamp, aborting the entire sync batch.

### H-06 NaN/Infinity timeout_seconds bypasses validation in CommandIntentAdapter
**File:** broker/adapters.py:130
**Evidence:** `float('nan') <= 0` evaluates to False; NaN passes the guard. subprocess.run(timeout=nan) hangs indefinitely.
**Why it matters:** Every other numeric validator in the broker package calls math.isfinite; this one omits it.

### H-07 Sharpe ratio formula computes annualized volatility, not Sharpe ratio (first occurrence)
**File:** scripts/analytics.py:106
**Evidence:** `stddev * SQRT(252)` — missing mean return in the numerator.
**Why it matters:** annual_sharpe field in JSON output, CSV, and Telegram digests is wrong for every strategy. High-variance strategies appear best instead of worst. (Duplicate of H-13.)
**Fix:** `(AVG(net_profit) / NULLIF(stddev, 0)) * SQRT(252)`

### H-08 Max drawdown formula ignores temporal ordering (first occurrence)
**File:** scripts/analytics.py:109
**Evidence:** `(max_cumulative_pnl - min_cumulative_pnl)` — no temporal constraint; global MAX and global MIN.
**Why it matters:** For a monotonically rising strategy [1,2,3,4,5], formula returns 4 — a large spurious drawdown. Distorts Kelly sizing and risk-layer comparisons. (Duplicate of M-50.)
**Fix:** Running-peak window function: `MAX(running_max - cumulative_pnl)` where `running_max = MAX(cumulative_pnl) OVER (PARTITION BY type ORDER BY timestamp ROWS UNBOUNDED PRECEDING)`.

**Why it matters:** The test name is test_replay_returns_existing_id_without_double_execution but a real double-withdrawal bug cannot be caught.
**Fix:** `gemini.withdraw_usdc.assert_called_once()` after both execute_transfer calls.

### H-10 SSRF via unvalidated SUPABASE_URL — service key forwarded to attacker-controlled host
**File:** mm_pilot.py:263
**Evidence:** url taken directly from env var; SupabaseControlsClient sends `Authorization: Bearer {self._key}` on every request to that URL.
**Why it matters:** Supabase service key bypasses all Row Level Security. An attacker who can set env vars in Railway config redirects all authenticated control-poll requests to 169.254.169.254 or an external host and receives the admin key.
**Fix:** `url = assert_public_url(url, env_name='SUPABASE_URL', allow_http=False)` before constructing the client.

### H-11 SUPABASE_SERVICE_KEY transmitted without HTTPS enforcement
**File:** supabase_sync.py:78
**Evidence:** URL checked only for being non-empty; scheme never validated. PostgrestClient sends service key as Authorization Bearer on every request.
**Why it matters:** If SUPABASE_URL uses http://, the admin key is sent in plaintext. Any URL pointing to an internal IP also forwards the key verbatim.
**Fix:** `if not url.startswith('https://'): raise RuntimeError('SUPABASE_URL must use HTTPS')` immediately after the null check.

### H-12 `KalshiRewardTracker.estimate_daily_reward` always returns 0.0
**File:** market_maker.py:1101
**Evidence:** `(1 - avg_spread * 100)` — avg_spread is a decimal ratio (e.g. 0.03); multiplying by 100 gives factor = 1 - 3.0 = -2.0; always clamped to 0 by max().
